# テトリス 仕様書

Vite の学習を目的としたテトリスの仕様。

## 技術方針

| 項目 | 決定 | 理由 |
|---|---|---|
| ビルドツール | Vite | 学習対象 |
| 言語 | TypeScript | ミノの形・座標・ゲーム状態を型で表現できる |
| UI フレームワーク | React | 状態から画面を宣言的に描画する |
| 描画方式 | DOM（CSS Grid でマスを並べる） | CSS で見た目を調整しやすく、DevTools で確認しやすい |
| 回転方式 | SRS（壁蹴りつきの回転） | MVP ではシンプル回転で作り、Step 7 で SRS にした |

### 設計の原則

- **ゲームロジックは React に依存しない純粋な TypeScript** として書く（`src/game/`）。
  - 例：`canMove(field, piece, dx, dy): boolean`、`rotate(piece, field): Piece | null`
  - Vitest で単体テストできるようにする。
- **React は「状態を表示する」「入力を受け取ってロジックに渡す」役割**に限定する（`src/components/`、`src/hooks/`）。
- フィールドは `Cell[][]`（`0` = 空、`1`〜`7` = ミノの種類）で表す。描画方式を変えてもロジックに影響しないようにするため。

## A. ゲームのルール（ロジック層）

### フィールド
- 横 10 × 縦 20 マス（見える部分）。
- 出現位置のために、見えない上部 2 行を追加してもよい（実装時に判断する）。

### テトリミノ
7 種類。それぞれ 4 マスでできている。

| 種類 | 形 | 色 |
|---|---|---|
| I | `████` | シアン |
| O | `██` / `██` | 黄 |
| T | `.█.` / `███` | 紫 |
| S | `.██` / `██.` | 緑 |
| Z | `██.` / `.██` | 赤 |
| J | `█..` / `███` | 青 |
| L | `..█` / `███` | オレンジ |

### 出現
- フィールド上部の中央から出現する。
- 出現位置がすでに埋まっている場合はゲームオーバーになる。
- 次のミノは **7-bag** で選ぶ。7 種類を 1 袋にしてシャッフルし、袋が空になるまで順に出す。空の袋から取り出すときに新しい袋を作る。
- 袋の中身と乱数の状態（`rng`）は state に持ち、袋から取り出すかどうかは reducer が決める。新しい袋が要るときだけ、reducer が `rng` から袋を作り、`rng` を進める。同じ seed からは同じ順番でミノが出る。
- リスタート（ゲームオーバーから start）では、新しい袋から始める。

### 落下
- 一定間隔で 1 マス下に移動する（重力）。
- 落下間隔はレベルが上がるほど短くなる。

### 移動・回転
- 左右移動・ソフトドロップ：移動先が壁・床・固定ブロックと重なる場合は移動しない。
- 回転：**SRS**。回転後の形が壁やブロックと重なる場合は、壁蹴りの表（`src/game/srs.ts`）の候補を先頭から順に試し、最初に重ならなかった位置に動かす。どの候補でも重なるなら回転しない。I は専用の表を使う。
- O ミノは回転しても形が変わらない。

### ホールド
- 落下中のミノをホールドに入れ、ホールド中のミノがあれば入れ替える。
- ホールドが空なら、次のミノ（NEXT）を出し、袋から 1 つ取り出す。入れ替えのときは袋を使わない。
- ホールドから出したミノは、出現位置に初期の向きで出る。出現位置に置けないときはホールドを無視する。
- 1 つのミノにつき 1 回だけ。ミノが固定されたら、またホールドできる。
- リスタートするとホールドは空に戻る。

### 着地・固定
- 下に移動できなくなったら、その位置でフィールドに固定する。
- MVP ではロックディレイなし（着地したらすぐ固定する）。
- 固定したら、ライン消去の判定を行ってから次のミノを出す。

### ライン消去
- 横一列がすべて埋まった行を消す。
- 消した行より上にある行を、消した行数だけ下にずらす。
- 同時に複数行消せる（最大 4 行 = テトリス）。

### スコア

| 同時に消した行数 | 得点 |
|---|---|
| 1 | 100 × レベル |
| 2 | 300 × レベル |
| 3 | 500 × レベル |
| 4 | 800 × レベル |

- ソフトドロップ：1 マスごとに +1。
- ハードドロップ：落とした距離 1 マスごとに +2。

### レベル
- 開始時はレベル 1。
- 合計 10 ライン消すごとにレベルが 1 上がる。
- ライン消去の得点は、消す前のレベルで計算する（レベルが上がるのはその後）。
- 落下間隔の目安：`max(100, 1000 - (level - 1) * 100)` ミリ秒。

### ゲームオーバー
- 新しいミノが出現位置に置けないとき。

## B. 操作（入力層）

| キー | 動作 |
|---|---|
| ←, A, J / →, D, L | 左右移動 |
| ↓, S, K | ソフトドロップ |
| ↑ / X | 右回転 |
| Z | 左回転 |
| Space | ハードドロップ |
| C | ホールド |
| P / Esc | 一時停止 / 再開 |
| Enter | ゲーム開始 / リスタート |

- キーを押し続けたときの連続移動（DAS / ARR）は、MVP ではブラウザのキーリピートに任せる。

## C. 表示（描画層）

- フィールド：CSS Grid で 10 × 20 のマスを並べる。各マスはミノの種類に対応する色で塗る。
- 落下中のミノ：固定済みのフィールドと重ねて描画する（フィールドのデータ自体には書き込まない）。
- ゴースト：落下中のミノをそのまま真下に落としたときの位置に、薄く重ねて描画する。state には持たず、描画のたびに計算する。
- NEXT：次のミノを 1 つ表示する。
- HOLD：フィールドの左にホールド中のミノを表示する。1 回使ったあと（固定されるまで）は薄く表示する。
- スコア・ライン数・レベルを表示する。
- 画面の種類：タイトル画面・プレイ画面・一時停止の表示・ゲームオーバー画面。

## D. ゲームの進行（状態管理層）

### 状態遷移

```
title ──Enter──▶ playing ──P/Esc──▶ paused
                   ▲  │               │
                   │  └──◀──P/Esc─────┘
                   │  │
                   │  └─出現不可──▶ gameover
                   │                  │
                   └──────Enter───────┘
```

### ゲーム状態（イメージ）

```ts
type GameState = {
  status: 'title' | 'playing' | 'paused' | 'gameover'
  field: Cell[][]        // 固定済みブロック
  current: Piece | null  // 落下中のミノ
  next: PieceType        // 次のミノ
  bag: PieceType[]       // 7-bag の残り（next のあとに出る順）。空のこともある
  rng: number            // 乱数の状態。新しい袋を作るときに使い、進める
  hold?: PieceType       // ホールド中のミノ（playing / paused のときだけ）
  canHold: boolean       // 今ホールドできるか（playing / paused のときだけ）
  score: number
  lines: number
  level: number
}
```

- 状態の更新は `useReducer` で行い、`(state, action) => newState` の純粋関数として書く。
- ゲームループは `requestAnimationFrame` を使い、経過時間が落下間隔を超えたら `tick` アクションを送る。
