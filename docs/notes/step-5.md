# Step 5: ライン消去・スコア・レベル・ゲームオーバー

## 分かったこと

- 型の和集合と積集合の考え方。リテラルに直接書いた余分なプロパティは検知するが、スプレッドや変数を経由したものは検知しない。型で矛盾を消す構造にする場合はプロパティ同士の相関ではなく、判別用プロパティからプロパティの有無や型を判定できるようにする。（もしくはオプショナルなプロパティにして`never`）
- 2つの三項演算子から union 型の相関関係に合うか判定できない
  ```ts
  {
    status:  alive ? 'playing' : 'gameover'   // → 'playing' | 'gameover'
    current: alive ? next : undefined         // → Piece | undefined
  }: GameState                                // → 型エラー
  ```
- correlated union。別々に作られた union どうしの相関は追えない
- スプレッドで余計なプロパティが混ざらないか注意。型システムも検知せず矛盾したデータになる。(`{status: 'gameover', current: {...} }`)
- Extract<>, Exclude<> でunion型を狭めることができる

## ハマったこと

- 3項演算子の優先順位。カッコで囲むのが丸い
